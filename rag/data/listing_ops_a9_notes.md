# 跨境 Listing 运营检索与 A9/转化备忘

## 搜索与转化的双重目标
跨境 Listing 不是只把说明书翻译成外文。标题与五点需要同时服务：
1) 搜索匹配（类目词、属性词、场景词）；
2) 点击后转化（清晰利益点、规格可信、图片与文案一致）。
小团队常见瓶颈是「会卖货的人不会写多语」或「会翻译的人不懂检索词」。Listing Ops Agent 的定位是产出可审批的分钟级草稿，而不是替代最终运营判断。

## 诊断维度清单
- 空词 / 夸张词
- 关键词重复堆砌
- 目标站点主检索词缺失
- 多语 claim 不一致
- 禁限词与医疗/认证风险
- 规格数字来源不一致
- 移动端前段信息不足

每一项都应尽量规则化，以便评测。LLM 负责润色与多语组织；规则负责稳定打标。两者冲突时，以更严格的合规规则为准，并提交人工。

## 草稿生成约束
- 输入：SKU、中文卖点、类目、目标市场、可选品牌词表。
- 输出：EN 标题、EN 五点、DE 标题、DE 五点（可按市场裁剪）、diagnosis 列表、metrics。
- 禁止：捏造认证、捏造检测数据、捏造客户 ROI、直连修改线上 Listing。
- 允许：基于规则的去重与补词；基于检索的词表提示；基于 LLM 的句式改写（有密钥时）。

## Human-in-the-loop
LangGraph interrupt 挂起在 human_approve。审批人看到草稿与诊断后输入 approve/reject。
- approve → export 本地文件并写 audit。
- reject → 结束或回到修改输入（演示版直接 END）。
生产要接 durable checkpointer（SQLite/Postgres），防止进程重启丢失待审状态。

## 时间线预期（目标，非客户案例）
人工从零写 EN+DE Listing 常需数小时；代理草稿目标 5–15 分钟内产出，人工复核 15–30 分钟。是否真的省时间要用你们自己的工时日志验证，并在指标表里标注 target。

## 与本 RAG Demo 的衔接
把本备忘、标题指南、禁限词表切成 500–1000 token 块（块间重叠约 100 token），嵌入后写入本地 Chroma。
问答示例：
- 「标题重复词怎么处理？」
- 「哪些宣称不能写在宠物湿巾？」
- 「EN/DE 如何保持 claim 对齐？」
无 API Key 时返回检索片段与模板摘要；有 Key 时再生成最终回答。重排序默认关闭，可用 --rerank 打开基于词面重叠的轻量重排。

## 附录：五点描述写作提示
1. 第一点回应主购买动机（清洁方便、温和、便携）。
2. 第二点给规格与包装（片数、尺寸、密封）。
3. 第三点给材质与敏感点（竹纤维、无酒精——仅在真实时）。
4. 第四点给使用场景（出门、雨天泥爪、猫狗共用需谨慎表述）。
5. 第五点给护理/储存注意，避免医疗承诺。
每一点尽量短句，避免标题已出现的空洞词再次堆叠。德语五点注意名词性别与复合词，不要逐词硬译。

## 附录：导出与审计字段建议
export JSON 建议包含：sku、drafts、diagnosis、banned_hits、approver、timestamps、diagnose_ms、draft_ms、thread_id、glossary_version。
审计目的是可回放：出了合规事故时能回答「当时命中了什么、谁批的、导出了哪一版」。这比宣传自动化率更重要。

## 附录：评测集构建
至少准备 20 条标注样本：正常标题、重复词、空词、缺检索词、禁限词、多语不一致。
CI 跑规则命中；可选跑 RAG 检索命中率（问题→期望文档名）。
不要用「客户增长百分之多少」这类无法在本仓库复现的数字作为通过条件。

运营提交中文卖点与目标站点后，系统先做字段完整性检查（SKU、类目、市场）。
缺失必填则不进入诊断。诊断输出应稳定可测；同一输入多次运行，规则命中集合应一致。
草稿节点读取诊断与词表检索结果，优先修复 block 级问题，再优化可读性。
若 LLM 超时，回退到规则模板草稿，保证流水线可完成。人工审批界面应并排展示原文、诊断、草稿差异。

## 场景库：驳回后的续跑
人工 reject 时记录原因码：合规、品牌语气、检索词不足、翻译质量、图片不符。

若原因是词表过期，先升 glossary_version 再重建 RAG 索引（--rebuild），然后重跑诊断。

## 场景库：多 SKU 批次
批量任务按类目分组共享词表，按 SKU 隔离草稿与导出。
并发时每个 SKU 独立 checkpointer thread，禁止共享可变草稿缓冲。
批次结束后汇总：规则命中分布、平均 diagnose_ms、审批通过率、驳回原因 Top N。这些都可以在没有客户 ROI 的前提下衡量系统是否有用。
